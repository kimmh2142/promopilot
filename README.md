# PromoPilot — 홈쇼핑 프로모션 순증 이익 시뮬레이터 (시제품)

[![test](https://github.com/kimmh2142/promopilot/actions/workflows/test.yml/badge.svg)](https://github.com/kimmh2142/promopilot/actions/workflows/test.yml)

> LOTTE AX Challenge 2026 · [과제 3] 롯데홈쇼핑 프로모션 시뮬레이터 지원용 시제품

편성이 정해진 방송에서 **카드 할인 · 무이자 할부 · 사은품** 조합별로 예상 주문, 매출, **비용을 반영한 순증 이익**을 계산하고, 제약 조건 안에서 최적안을 추천합니다.
이 시제품의 목적은 화려한 기능이 아니라 **"계산이 정확한지 증명할 수 있는 구조"**를 먼저 만드는 것입니다.

## 핵심 아이디어

| 원칙 | 구현 |
|---|---|
| 매출이 아니라 순증 이익 | 혜택이 없을 때(기준선)와 비교한 이익 차이를 계산하고, 카드 분담률·사은품 원가·반품률을 반영 |
| 선택 편향 보정 | 혜택은 인기 상품·좋은 시간대에 몰립니다. 상품 고정효과와 시간대 통제로 '같은 상품의 조건 차이'에서 효과를 추정 |
| 하나의 검증 가능한 모델 | 고객군(신규·기존·휴면)별 로그 주문량 회귀. 혜택 효과는 단조 제약(음수 금지) |
| 불확실성 공개 | 부트스트랩으로 주문·순증 이익의 90% 범위 제시 |
| 외삽 경고 | 과거에 쓰인 적 없는 조건(예: 15% 할인)은 추천에서 빼고 A/B 실험 후보로 따로 표시 |
| LLM은 숫자를 만들지 않는다 | 계산은 도구가, LLM은 요청 구조화와 설명만. 설명문 숫자를 도구 결과와 자동 대조(`verify_numbers`) |

## 검증 방법: 파라미터 복원 테스트

실제 데이터가 없는 단계에서는 "모델이 맞는지"를 확인할 정답이 없습니다. 그래서 **효과 크기를 미리 정해 둔 합성 데이터**를 만들고, 모델이 그 값을 다시 찾아내는지 확인합니다. 선택 편향도 일부러 넣어 보정이 실제로 동작하는지 함께 봅니다.

`python demo.py` 실행 결과 일부:

| 고객군 | 혜택 | 정답 | PromoPilot 추정 (95% 구간) | 단순 회귀 추정 |
|---|---|---|---|---|
| 신규 | 카드 할인 | 0.45 | 0.451 (0.437~0.464) | 0.841 |
| 기존 | 사은품 | 0.35 | 0.346 (0.327~0.369) | 1.064 |
| 휴면 | 카드 할인 | 0.55 | 0.549 (0.534~0.564) | 0.945 |

통제 없는 단순 회귀는 효과를 2배 이상 부풀리고, PromoPilot은 정답을 구간 안에서 되찾습니다. 전체 결과는 [`results/demo_report.md`](results/demo_report.md)에 있습니다.

> 합성 데이터로 확인할 수 있는 것은 **구현의 정확성**입니다. 실제 프로모션 효과 크기나 매출 개선 폭은 실제 데이터로 백테스트해야 알 수 있습니다.

## 데모 시나리오

> "가전-03 화요일 저녁 프라임 방송, 이익률 20% 이상, 사은품 300개 안에서 순증 이익 최대 조합 찾아줘"

1. 요청을 도구 호출로 구조화 → `optimize_promotion(product_id, timeslot, weekend, min_margin, gift_stock)`
2. 후보 54개 조합 전수 계산 → 이익률·재고·외삽 조건으로 거르기
3. 상위 3안을 기준선 대비 순증 이익과 범위로 제시, 고객군별 예상 주문 표시
4. "카드사가 50% 분담하면?" → 다시 계산하면 최적 할인율이 7%에서 10%로 바뀜 → **협상 포인트**
5. 학습 범위 밖 15% 할인은 더 좋아 보여도 추천하지 않고 실험 후보로 표시
6. 설명문의 숫자를 도구 결과와 대조 → 틀린 숫자가 들어간 설명은 차단

## 구조

```
promopilot/
├── promopilot/
│   ├── config.py       # 정답 효과, 후보 조건, 비용 파라미터(가정값)
│   ├── data_gen.py     # 선택 편향을 넣은 합성 방송 데이터 생성기
│   ├── model.py        # 고객군별 반응 모델, 부트스트랩 범위, 외삽 판정
│   ├── optimizer.py    # 이익 계산(규칙), 전수 탐색 최적화
│   └── agent_tools.py  # LLM 도구 스키마, 도구 실행·입력 검증, 수치 대조
├── tests/test_promopilot.py   # 복원·편향·제약·외삽·입력 검증·수치 대조 테스트
├── demo.py             # End-to-End 데모 → results/demo_report.md
└── requirements.txt
```

## 실행

```bash
pip install -r requirements.txt
python demo.py      # 데모 실행, 결과 리포트 생성
pytest -q           # 테스트 8개
```

## 가정과 한계

- 비용 구조(수익률 30%, 카드 결제 비율 80%, 분담률 등)는 **가정값**이며 `config.DEFAULT_COSTS`에서 실제 계약 조건으로 바꿉니다.
- 모델 함수 형태(할인 효과의 로그 체감 형태)가 실제와 다르면 추정이 틀릴 수 있습니다. 실제 데이터에서는 형태 비교와 시간순 검증(MAE, WAPE)이 필요합니다.
- 관측되지 않은 요인(쇼호스트, 경쟁 방송 등)이 혜택 배정에 영향을 주면 고정효과 보정만으로는 부족합니다. 그래서 추천안 일부를 A/B 테스트로 확인하는 절차를 전제로 합니다.
- TV 방송 혜택은 시청자 전체에게 같은 조건이 적용되므로, 개인 단위 업리프트 모델 대신 고객군 단위 반응을 추정합니다.
